# 试玩反馈清单

本文件记录第一版 MVP 试玩期间确认的问题与后续内容方向。功能 MVP 已完成，但内容表现仍需要继续打磨。

## 已确认的内容问题

### 背景音乐与声音氛围

- 状态：正式封面配乐与 MVP 音频系统已实现，场景和关键事件专属音乐待补充
- 当前实现：首次有效点击后循环播放传统器乐曲《月夜随想 Thoughts on a moonlit night》；普通按钮、剧情选择、确认和关键线索继续使用 Web Audio 分级音效。音乐和音效分别提供静音、音量控制，并持久保存玩家设置。
- 素材与离线：配乐来源和许可记录在 `docs/assets/audio/README.md`，压缩后的 MP3 已纳入 PWA 离线缓存；媒体 API 不完整时会安全降级，不阻断游戏流程。
- 后续目标：按场景补充可循环音乐和关键事件音乐，并保留现有解锁、控制、持久化及短音效机制。
- 交互音效：普通按钮点击、确认结果、剧情选择、获得关键线索使用层级不同但克制的声音反馈；避免所有按钮重复同一种突兀音效。
- 设置要求：玩家的音乐和音效设置需要持久保存，首次有效交互后再启动声音，不绕过浏览器自动播放限制。
- 注意事项：需要处理浏览器自动播放限制、移动端兼容、切换场景时的淡入淡出，以及离线缓存音频资源。

### 序章表现过于简略

- 状态：五幕叙事已扩充，待继续视觉打磨
- 当前问题：序章虽然具备五幕结构，但目前更像剧情骨架，情绪铺垫、人物对白、场景调度和悬念不足。
- 当前实现：五幕均已补充环境细节、角色动作、对白或内心段落；从廖宅日常、黑衣人突袭、母亲牺牲、李慕尘救援递进到十五年后的复仇动机。继续阅读和跳过序章逻辑保持不变。
- 后续目标：在不影响可读性和减少动态偏好的前提下，为序章补充更贴合幕次的场景视觉和极克制的氛围动态。
- 内容要求：保留逐幕阅读和跳过功能；扩充对白、动作和环境细节；为后续李慕尘对决与最终选择埋下可回收的伏笔。

### 日常行动缺少事件变化与状态代价

- 状态：已实现，九项日常行动全部接入具体事件；公务、训练、社交、调查和赚钱均有独立事件与分支结果
- 当前问题：后续仍可继续扩写事件数量，但基础的重复行动变化和状态代价已经具备。
- 试玩建议：同一种日常行动应从事件池中抽取不同事务。例如第一次巡街由周寒川带教，之后可能遇到闹市狂徒、失窃报案或相安无事；玩家可以选择出手、不出手、观察或追查，不同选择产生不同属性、关系、财富、风险和后续旗标影响。
- 设计要求：行动类型保留原有成本和解锁条件，但执行后进入一个具体日常事件；事件选项必须有清晰的即时结果，并允许部分事件在后续月份再次以不同变体出现。
- 新状态建议：新增“健康值”作为独立状态，受到受伤、熬夜、饮酒、过度训练和部分公务选择影响，并能反过来影响行动成功、可选项或叙事表现。具体上限、恢复方式和存档兼容方案在实现前单独确定。
- 当前实现：巡街执勤和协助办案会按执行次数轮换具体事件；训练、社交、调查和赚钱也会进入各自事件分支。选择会影响声望、智谋、关系、财富、风险和健康值。健康值初始 100，范围 0–100，旧存档缺字段时自动迁移为 100。
- 后续目标：继续扩写同一行动的更多变体，并让事件权重进一步受月份、风险、健康值、关系和已知线索影响。

### 调查线索、风险与月度随机性不足

- 状态：主线调查链已补齐第 2 月节点，月度随机事件已接入第 1、2、3 月；风险和健康值会在事件选择中产生实际后果
- 当前问题：第一章结束时主要呈现“烧焦木牌·清晰”这一条线索，调查过程像一次直接升级，缺少取证、误判、回访和多条证据互相印证的过程。
- 当前问题：风险主要表现为单一等级条，玩家不清楚风险从哪里来、会触发什么具体后果，也缺少“暂时压下去”或“冒险换线索”的选择张力。
- 当前问题：随机事件的数量和条件权重仍可继续扩写，但每个月已经有独立突发，行动之外会出现司内点名、街面骚乱或雨夜加差。
- 后续目标：让随机事件权重进一步受健康值、关系和已知线索影响，并继续扩展同类事件的变体。
- 重点约束：每个月最多触发有限数量的随机事件，随机事件服务于人物、风险或线索，不得替代或遮蔽当月主线；主线节点需要有明确的章节标签、线索推进和阶段性目标，让玩家始终知道当前正在追查什么。
- 计划顺序：先建立“月度主线节奏表”，再在每月主线间隙插入条件化随机事件；随机事件的权重受月份、风险、健康值、关系和已知线索影响，但主线节点仍按条件稳定触发。

### 主线事件缺少专属配图，页面表现过于简易

- 状态：首个重点已实现，后续主线节点待继续补图
- 当前问题：以“月末·廖宅旧物”为代表的主线事件只有标题、短文本和选项按钮，留白过多，缺少明确的视觉主体，看起来更像普通系统提示而不是关键剧情。
- 当前实现：第 1 月末“烧焦的木牌”事件已接入专属横版事件图，原始 PNG 归档于 `docs/assets/events/charred-token-event-v1.png`，页面使用压缩 JPG 并保留语义化替代文本；图片已随现有 PWA 静态资源策略进入离线缓存。
- 后续目标：为其他重要主线节点配置专属场景图或关键物件图，使人物、地点或证物成为第一视觉信号。
- 首个重点：为“烧焦木牌”事件制作木匣、焦黑木牌、残缺“云”字与“商行”字样的近景插图，强化它作为复仇主线第一条线索的分量。
- 界面要求：配图需与标题、正文和选择形成完整事件构图；桌面与移动端都不能出现大面积无意义留白、文字遮挡或横向滚动。
- 美术要求：图片必须直接表现当前剧情，不使用与事件无关的通用古风背景或纯装饰素材；关键图片需要合理的替代文本并纳入离线缓存。

### 进入新月份前缺少上月收获总结

- 状态：已实现，待继续视觉打磨
- 当前问题：月末事件结束后直接显示下一月份和“新的月份开始了”，玩家看不到上个月完成了哪些行动、获得了什么，也缺乏清晰的阶段结束感。
- 后续目标：每个月结束时先进入动态月度结算页，玩家确认总结后才进入下一月的月初页。
- 总结内容：本月行动与关键事件、属性变化、财富变化、人物关系变化、风险变化、新增或升级的线索，以及影响后续剧情的关键选择。
- 呈现方式：同时展示具有叙事感的月度评语和清晰的数值变化；没有发生变化的项目不占据主要版面。
- 数据要求：结算必须依据玩家本月真实操作生成，不能使用与实际选择无关的固定总结文本；刷新或读取存档后仍能准确恢复。
- 流程要求：`本月行动/事件 → 月度结算 → 玩家确认 → 下一月月初 → 开始本月`，第 3 月结束时则由月度结算进入“第一章完成”。
- 当前实现：结算会冻结并展示当月真实行动、关键事件、叙事结果与效果摘要；结算数据随存档保存，第 3 月确认结算后进入“第一章完成”。

### 剧情选择结果页过于简陋

- 状态：已实现，待继续补充专属视觉
- 当前问题：以冯天顺“旧友”结果页为代表，页面只有一句结果文字和“确认结果”按钮，缺少人物、环境、情绪和选择后果的视觉呈现，大面积留白削弱了剧情重量。
- 当前实现：结果页保留选择后的完整叙事，并新增“选择带来的变化”区域，直接展示关系、财富、线索和状态等效果；没有数值变化时也会显示明确的反馈文本。结果页已在 390px 和 320px 移动视口检查无横向溢出。
- 后续目标：为重要人物事件补充与结果匹配的立绘、局部场景或专属事件图，让剧情反馈进一步形成完整场景。
- 叙事内容：补足人物动作、对白、主角观察或内心反应；不同选择应有明显不同的情绪收束。
- 结果信息：在当前页明确展示关系变化、属性或财富变化、获得线索、解锁内容和重要flag，不应要求玩家去侧栏或历史记录中自行寻找。
- 视觉要求：重要人物事件使用人物立绘、局部场景或专属事件图；画面应与选择结果匹配，不复用无关素材填充空间。
- 交互反馈：点击剧情选择和“确认结果”时提供适度音效；关键关系变化或线索获得可以使用更明确但不过度的声音提示。

### 游戏封面缺少紧张、肃杀和高级感

- 状态：全屏响应式封面已实现并通过桌面与移动端视觉验收
- 当前实现：封面已改为全屏叙事主视觉，桌面使用横版锦衣卫场景，760px 及以下使用独立竖版构图；标题、剧情简介和开始按钮直接叠在画面安全区。
- 验收结果：已在 1440×900、390×844 和 320×720 三档视口检查人物裁切、文字可读性、按钮位置和横向溢出；均正确加载对应封面且控制台无警告或错误。
- 后续目标：在不影响可读性和减少动态偏好的前提下，评估是否加入非常克制的雨、烛火或烟尘动态。
- 画面主体：身着飞鱼服的锦衣卫主角、北镇抚司或诏狱环境，以及案牍、绣春刀、雨、火光或血迹等与主线直接相关的细节；画面需要暗示“身在权力中心追查灭门旧案”。
- 美术方向：写实或高完成度电影概念美术，冷黑与铁灰为环境基调，以暗红和克制金色作权力与危险信号；强调强明暗、纵深和材质细节，避免廉价扁平矢量、通用古风壁纸、发光渐变和装饰性光斑。
- 构图要求：使用全幅位图场景作为背景，标题与操作直接叠在画面安全区，不把主视觉放进卡片；桌面和移动端分别保证人物、绣春刀与标题不被错误裁切或互相遮挡。
- 动态与声音：可加入非常克制的雨、烛火、烟尘或远处脚步氛围，但必须支持减少动态效果；进入封面、开始或继续游戏时配合低沉而短促的声音反馈。

## 试玩记录原则

- 内容体验问题与程序 Bug 分开记录。
- 每个程序 Bug 尽量附带复现步骤、期望结果和实际结果。
- 在开始音频或序章重写前，先完成当前 MVP 的试玩反馈收集。
