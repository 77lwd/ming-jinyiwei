# ADR-001：采用电脑端优先的章节与自由窗口运行模型

## 状态

Superseded by ADR-002

## 日期

2026-09-06

## 背景

旧 MVP 以月份、可重复日常事件、月末结算和风险值驱动。这个运行模型与已经确认的完整设计冲突：游戏应由序章、五章主线、7 个自由行动窗口、固定阶段事件和独立突发事件组成；风险值、月度事件和日常事件循环不再是规则。

旧界面还包含移动端状态抽屉、行动抽屉和 PWA 构建入口。当前实现阶段需要先确保电脑端三栏阅读、选择和状态反馈稳定，再考虑其他端。

## 决策

1. 新运行状态以 `chapter`、`mainlineNode`、`freeActionWindowIndex` 和 `completedFreeActionWindows` 为核心，不再使用月份推进、风险等级或行动点循环。
2. 每个自由行动窗口最多安排一项行动，也可以显式跳过；健康只能改变行动代价或可选做法，不能吞掉窗口。
3. 旧月份／日常／风险代码与旧测试从 `src/` 和 `e2e/` 的可执行入口移除；历史规格和试玩记录保留并标注为历史依据。
4. 存档使用版本 2；发现版本 1 的旧存档时只提示重新开始，不自动解释、不覆盖原值。
5. 暂时移除移动抽屉、移动端响应式分支和 PWA 构建插件，Playwright 只保留桌面项目。

## 放弃的替代方案

### 保留旧月份系统并在上面叠加章节字段

拒绝：会让月末锁定、风险反噬和无限日常事件继续从隐性入口影响新流程，难以证明自由窗口真的独立。

### 先实现移动端，再回头收敛桌面布局

拒绝：会把状态抽屉、底部行动抽屉和窄屏断点继续固化，增加当前电脑端阅读长文本与多栏状态的改造成本。

### 删除所有旧文档与旧素材

拒绝：历史文档仍用于追溯决策和核对已经废弃的设想，但不再作为运行规则。

## 后果

- 当前代码可以明确验证“章节状态存在、7 个窗口可达、低健康仍可行动、旧存档不会静默迁移”。
- 完整五章内容、4 个阶段事件和5个突发事件仍需按既定计划逐个接入。
- 运行时暂时失去旧 MVP 的月度试玩路径；这是有意的过渡状态，下一检查点必须补上新主线入口后再进行试玩。
