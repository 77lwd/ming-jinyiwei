# 第二章《失号凭照》实施计划

## 一、目标

在不改写第一章的前提下，把第二章从占位节点实现为可玩的三案主线，并在章末完成总簿核验、跨章状态写入和第三章桥接。实现遵循现有桌面端 React/TypeScript 架构，沿用第一章已验证的叙事、案件记录、证据工作台和结果反馈模式。

## 二、不可改动范围

- 第一章正文、证据精确匹配规则、夜间“雇人守住火场残料”费用（银两 `-5`、健康不减）；
- 第一章已有属性、资源、人脉与证据状态语义；
- 月份、风险、自由行动、随机事件和旧月份存档解释；
- 正式图片生成与外部素材制作。

## 三、任务顺序

### Task 1：完成第一章到第二章的最小交接

**涉及文件：** `src/components/ChapterComplete.tsx`、`src/engine/gameEngine.ts`、相关 store/types 测试。

- 增加“进入第二章”动作；
- 仅在 `chapter1` 结章状态允许切换；
- 切换时当前银两 `+5`，记录可见的奖励原因；
- 使用章节切换本身保证一次性，重复点击或恢复存档不得重复奖励；
- 不改变第一章内部节点和结案逻辑。

**验收：** 结章页进入第二章可达；奖励幂等；第一章回归测试通过。

### Task 2：建立第二章数据与最小类型边界

**涉及文件：** 新增 `src/data/chapter2.ts`、`src/types/game.ts` 或等价章节类型文件、数据测试。

- 录入开章、三案、总簿核验和第三章桥接节点；
- 为三案定义材料、固定事实、待核问题、互斥调查顺序和结果叙事；
- 复用现有 `health_change`、`wealth_change`、属性和关系效果类型，不新增资源类别；
- 旧 `chapter2.paper-note-review` 从装配表移除。

**验收：** 数据可静态装配；所有状态名称与跨章基线完全一致；不得出现旧循环字段。

### Task 3：实现三案的案件状态与调查顺序

**涉及文件：** `src/engine/gameEngine.ts`、案件状态类型、第二章引擎单测。

- 实现 `slip_chain_1/2/3` 完成摘要；
- 每案严格写入一个互斥分支；重复选择不可重复写入；
- 调查顺序改变证据保留与对白，不改变案件完成可达性；
- 廖威达动作受普通校尉权限限制，覃保坤承担批准、看守、封存和程序责任；
- 未明确标价的动作不改变健康或银两；不自动发放属性点。

**验收：** 三案顺序、互斥约束、权限边界、资源白名单测试通过。

### Task 4：实现总簿核验与第三章桥接

**涉及文件：** `src/data/chapter2.ts`、`src/engine/gameEngine.ts`、状态/记录组件和测试。

- 增加专用总簿核验节点；
- 核验只允许百户所总簿与三案材料进入工作台；
- 正确写入 `c2_transfer_room_identified`、`c2_register_copy_preserved`、`c2_register_tampered`；
- 核验完成后直接转入第三章入口，不再经过纸条线索占位节点；
- 不把总簿异常解释为高层身份或烧焦木牌来源。

**验收：** 三个固定状态全部写入；错误材料组合不能通过；第三章入口可达。

### Task 5：接入案件记录、状态反馈与资源展示

**涉及文件：** `src/components/CaseRecord.tsx`、`src/components/CaseWorkbench.tsx`、必要的新核验组件、`src/components/ResultPanel.tsx`、样式文件。

- 让玩家能看见当前案件、已固定证据、待核问题、分支差异和结算结果；
- 章节进入时显示“第一案结案补贴：银两 +5”；
- 明确显示任何已确认资源代价；当前第二章若无额外标价选择，不显示虚构费用；
- 继续遵守桌面端可读性、键盘可达、缺图不阻断和无卡套卡的产品规范；
- 第一章界面仅做必要的章节入口兼容，不做视觉重写。

**验收：** 关键流程渲染测试、键盘操作测试和桌面浏览器回归检查通过。

### Task 6：补齐存档与回归测试

**涉及文件：** `src/store/saveRepository.ts`、`src/store/__tests__/saveRepository.test.ts`、`src/engine/__tests__/gameEngine.test.ts`、第二章数据/组件测试。

- 保存并恢复第二章当前节点、三案完成摘要、互斥分支和章末固定状态；
- 验证 `+5` 奖励不会因刷新、重复点击或读档重复结算；
- 验证旧月份/风险字段不会被新流程重新启用；
- 第一章既有测试全量通过。

**验收：** `npm run typecheck`、项目测试命令和必要的桌面浏览器检查全部通过。
