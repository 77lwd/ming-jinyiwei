# 第一章《纸灰里的银子》可玩性重塑实施计划

日期：2026-09-09  
状态：待玩家审阅与确认  
对应规格：[2026-09-09-chapter1-playability-rebuild.md](../specs/2026-09-09-chapter1-playability-rebuild.md)

## 范围锁定

本计划只实现第一章《纸灰里的银子》的可玩性重塑。第一章通过玩家可玩性验收前，不开发第二章及后续章节，不扩展通用章节骨架，不新增自由行动窗口、风险系统、全局数值或未经确认的人物关系字段。

## 实施原则

- 先测试后实现：每个行为先写能证明当前缺失的测试。
- 垂直薄切片：每完成一个可独立试玩的切片，就运行测试并汇报可见成果。
- 沿用现有状态机、存档版本、图片路径和 UI 外壳；只替换第一章内部的调查与结案逻辑。
- 证据采用轻量命题核验，不制作拖拽拼图、战斗、随机真凶或审判模拟。
- 所有失败都可补正，案件主线不因一次错误选择锁死。

## 依赖关系

```text
调查状态与证据模型
        ↓
第一日两次调查
        ↓
证据命题核验
        ↓
夜间取舍与第二日状态
        ↓
人物交锋与覃保坤请示
        ↓
玩家结案提交
        ↓
案件结果、木牌、冯天顺与存档回归
        ↓
第一章低保真试玩与可玩性验收
```

## 任务清单

### 阶段 1：状态与证据基础

#### Task 1：定义第一章调查状态和证据类型

**目标：** 为第一章增加局部调查进度、已取得材料、已固定事实、待证问题和缺口表示，复用现有类型风格，不引入全局新系统。

**验收标准：**

- [ ] 能表示三条调查路线及其独特材料；
- [ ] 能区分“已取得”“已固定”“相关但不足”“尚未取得”；
- [ ] 状态可被存档与恢复；
- [ ] 不改变既定跨章状态字段。

**验证：** 新增单元测试；运行 `npm test -- --run src/data/__tests__/chapter1.test.ts` 与 `npm run typecheck`。

**可能涉及文件：** `src/types.ts`、`src/data/chapter1.ts`、现有状态 reducer/store 文件、`src/data/__tests__/chapter1.test.ts`。

**依赖：** 无。  
**范围：** 中。

#### Task 2：实现第一日“两次优先调查”规则

**目标：** 将三选一自动汇合改为第一日最多优先完成两条路线，第三条保留为第二日补证入口。

**验收标准：**

- [ ] 第一次调查后仍停留在第一日调查阶段；
- [ ] 第二次调查后进入夜间阶段；
- [ ] 已完成路线不可重复领取同一材料；
- [ ] 未选路线不会提前写入证据或结论；
- [ ] 第一日不新增自由行动窗口。

**验证：** 测试三种路线组合及重复点击；运行相关测试和 `npm run typecheck`。

**可能涉及文件：** `src/data/chapter1.ts`、章节流程 reducer、`src/data/__tests__/chapter1.test.ts`。

**依赖：** Task 1。  
**范围：** 中。

### 检查点 A：第一日可玩切片

- [ ] 玩家能完成两次不同调查；
- [ ] 每次调查获得不同材料；
- [ ] 第三条路线尚未被揭示；
- [ ] 全部测试和类型检查通过；
- [ ] 暂停并汇报实际可试玩变化。

### 阶段 2：证据核验与办案边界

#### Task 3：实现轻量证据命题核验

**目标：** 让玩家使用已取得材料回答局部待证问题，区分直接支持、相关但不足、冲突和未取得。

**验收标准：**

- [ ] 未取得材料不能被选择；
- [ ] 相关但不足的组合不会错误固定事实；
- [ ] 直接支持的组合能固定对应事实；
- [ ] 错误提交可以重新核验；
- [ ] 核验结果不会直接泄露幕后真相。

**验证：** 为每个待证问题添加正例、反例和补正测试；运行 `npm test`。

**可能涉及文件：** `src/data/chapter1.ts`、证据判断 helper、`src/data/__tests__/chapter1.test.ts`。

**依赖：** Task 1、Task 2。  
**范围：** 中。

#### Task 4：接入覃保坤请示与权限流程

**目标：** 将查访、勘验、整理、封存、调差役和暂扣等行为区分为廖威达建议与覃保坤批准，体现锦衣卫校尉权限边界。

**验收标准：**

- [ ] 廖威达不能直接执行封存、调人、暂扣和主持复核；
- [ ] 玩家可以提交办案建议并看到覃保坤批准或要求补证；
- [ ] 覃保坤反馈指出证据边界，不直接宣布真凶；
- [ ] 请示结果写入第一章局部状态。

**验证：** 添加权限边界和补证路径测试；运行 `npm test` 与 `npm run lint`。

**可能涉及文件：** `src/data/chapter1.ts`、流程 reducer、覃保坤反馈数据、相关测试文件。

**依赖：** Task 3。  
**范围：** 中。

### 阶段 3：夜间取舍与第二日

#### Task 5：实现夜间三选一的真实后果

**目标：** 让整理、看望吴生、守住残料三条路线分别改变第二日材料、人物态度或办案成本。

**验收标准：**

- [ ] 三种选择写入不同局部状态；
- [ ] 第二日能读取并展示对应影响；
- [ ] 健康或银两变化只在既定具体行为中发生；
- [ ] 每条路线都有可完成案件的替代证明路径；
- [ ] 不改变自由行动数量。

**验证：** 为三种夜间路线分别编写状态和替代路径测试；运行 `npm test`。

**可能涉及文件：** `src/data/chapter1.ts`、状态效果处理、`src/data/__tests__/chapter1.test.ts`。

**依赖：** Task 2、Task 3、Task 4。  
**范围：** 中。

#### Task 6：实现第二日补证与人物交锋

**目标：** 根据第一日缺口和夜间选择，提供补证顺序、贺兴说法反应、吴生当面对质条件和覃保坤主持的程序反馈。

**验收标准：**

- [ ] 单项证据不足时，贺兴可以暂时圆说法；
- [ ] 两项以上相互咬合的证据可以暴露矛盾；
- [ ] 吴生是否愿意当面对质受夜间选择和既往对待影响；
- [ ] 玩家可以通过替代路径补齐关键事实；
- [ ] 覃保坤主持程序，廖威达提出依据。

**验证：** 添加至少两种证据缺口场景、两种夜间路线和两种交锋方式的流程测试。

**可能涉及文件：** `src/data/chapter1.ts`、交锋/核验 helper、流程 reducer、测试文件。

**依赖：** Task 5。  
**范围：** 大，必要时拆为 6a/6b 两个提交切片。

### 检查点 B：第二日可玩切片

- [ ] 第一日不同路线能导致不同第二日材料或反应；
- [ ] 玩家至少需要一次证据核验；
- [ ] 覃保坤请示和权限边界可感知；
- [ ] 证据不足时能补正而不是卡死；
- [ ] 全部测试、类型检查和 lint 通过；
- [ ] 暂停并汇报实际可试玩变化。

### 阶段 4：玩家结案与回归

#### Task 7：实现玩家结案提交

**目标：** 将自动结案改为玩家提交责任判断、关键依据和处置建议，合格后才进入依法结案。

**验收标准：**

- [ ] 责任判断、依据组合和处置建议均可提交；
- [ ] 不合格提交明确指出缺口并允许补正；
- [ ] 当众复核和暂不点破两种合格方案都能结案；
- [ ] 结案结果体现证据完整度、人物压力和覃保坤评价差异。

**验证：** 添加合格、缺证、不匹配和补正测试；运行 `npm test`。

**可能涉及文件：** `src/data/chapter1.ts`、结案判断 helper、流程 reducer、测试文件。

**依赖：** Task 6。  
**范围：** 中。

#### Task 8：接回既定案后节点与存档

**目标：** 保持结案后木牌入档、冯天顺重逢和三项跨章状态的既定顺序，并验证中途存档恢复。

**验收标准：**

- [ ] 合格结案写入 `first_case_closed`；
- [ ] 木牌节点写入 `charred_token_preserved`；
- [ ] 冯天顺节点写入 `tianshun_reconnected`；
- [ ] 状态写入顺序不变；
- [ ] 调查中途存档恢复后可继续，不重复发放证据或效果。

**验证：** 运行章节回归测试、存档恢复测试、`npm run typecheck`、`npm run lint`、`npm run build`。

**可能涉及文件：** `src/data/chapter1.ts`、存档/状态模块、章节测试。

**依赖：** Task 7。  
**范围：** 小至中。

### 检查点 C：第一章逻辑完成

- [ ] 第一章从标题页可完整玩到结案、木牌和重逢；
- [ ] 没有第二章人物或信息越界；
- [ ] 所有既定跨章状态和权限边界保持不变；
- [ ] `npm test`、`npm run typecheck`、`npm run lint`、`npm run build` 全部通过；
- [ ] 交给玩家进行低保真试玩。

### 阶段 5：第一章 UI 接入与试玩

#### Task 9：把新调查状态接入现有案件工作台

**目标：** 在现有第一章 UI 外壳中显示待证问题、已取得材料、证据核验、请示反馈、夜间后果和结案提交，不重做全局视觉。

**验收标准：**

- [ ] UI 只显示玩家已知信息；
- [ ] 调查按钮显示当前可用路线和已完成状态；
- [ ] 证据核验、请示和结案提交有清晰反馈；
- [ ] 属性资源和人脉不遮挡案件核心流程；
- [ ] 案件抽屉和 tooltip 不越界。

**验证：** 运行现有组件测试、浏览器桌面检查和控制台检查；不做移动端适配。

**可能涉及文件：** `src/components/CaseWorkbench.tsx`、`src/components/CaseRecord.tsx`、`src/components/ResultPanel.tsx`、`src/styles/app.css` 及相关测试。

**依赖：** 检查点 C。  
**范围：** 中。

#### Task 10：玩家低保真试玩与可玩性复审

**目标：** 由玩家从标题页实际试玩第一章，记录具体操作路径和无聊、困惑、缺乏选择意义的位置。

**验收标准：**

- [ ] 玩家能说出自己做过的关键判断；
- [ ] 玩家能复述吴生被排除的理由和贺兴被锁定的证据链；
- [ ] 玩家能感受到查访、勘验、核验、请示和处置的区别；
- [ ] 覃保坤特点能通过互动被感知；
- [ ] 可玩性评分达到至少 `35/50`，否则回到问题定位，不进入第二章。

**验证：** 创建新的试玩反馈文件，更新可玩性评分和待修问题；必要时运行 `npm test`、`npm run build` 并进行真实桌面浏览器检查。

**依赖：** Task 9。  
**范围：** 中。

## 检查点后的决策门

- 检查点 A：确认第一日调查是否已经不再是单次跳转。
- 检查点 B：确认夜间和第二日是否产生真实策略差异。
- 检查点 C：确认案件逻辑完整后才接入 UI。
- 检查点 D：玩家可玩性验收通过后，才允许制定第二章计划。

## 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 新状态与旧存档结构冲突 | 高 | 先写恢复测试，必要时使用向后兼容的默认空调查状态 |
| 路线差异变成隐藏最优解 | 中 | 保持不同收益与代价，不让任何一条成为唯一通关条件 |
| 证据系统过度复杂 | 中 | 使用命题核验，不做拖拽拼图和随机组合 |
| 覃保坤变成答案提示器 | 中 | 反馈只说明证明边界和程序选择，不直接公布真凶 |
| UI 重新堆满信息 | 中 | 案件核心优先，属性资源放入档案抽屉，人脉只显示确认信息 |
| 玩法改动误触后续章节 | 高 | 所有测试和变更限定 `chapter1`，检查点 C 做跨章状态回归 |

## 暂不做

- 第二章及后续章节；
- 新自由行动窗口、月份、风险或重复日常循环；
- 新的全局人物关系字段；
- 移动端、PWA、商店、素材生成；
- 复杂拖拽案件板、战斗和完整审判模拟。

## 计划确认门

玩家确认本计划后，才进入 Task 1 的测试先行实现。每个检查点完成后先汇报实际可玩变化，再继续下一阶段。
