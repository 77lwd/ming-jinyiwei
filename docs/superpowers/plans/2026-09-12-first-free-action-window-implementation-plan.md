# 第一个自由行动窗口实施计划

日期：2026-09-12  
状态：Task 1—Task 5 已实施；自动化验收通过，等待第二章正文接入后进行自然流程试玩

## 一、目标

把当前用于技术验证的单层自由行动按钮替换为已确认的“地点 → 行动 → 资源及叙事结算”流程。范围只包括第二章第一案后的第一个自由窗口，不扩写第二案，不制作其余六个窗口。

## 二、固定边界

- 每个窗口只能完成一项主要行动，也可以无惩罚跳过；
- 行动影响已有属性、健康、银两、声望或已认识人物的看法；
- 不显示人物关系数值，普通拜访不改变关系阶段；
- 不生成案件证据，不提前调查《空屋里的嫁妆》；
- 不恢复月份、行动点、风险、日常循环或旧通用行动菜单；
- 当前临时行动数据必须迁移，不与正式行动并存。

## 三、实施任务

### Task 1：锁定正式数据契约与平衡测试

**内容：** 为地点、行动、强度、资源效果、人物看法结果和章节成长上限建立最小数据结构；先写失败测试。

**验收：**

- 住处、医馆、校场、署内、城中、人脉六个地点可表达；
- 恢复比例与正式规格一致；
- 数据中不存在关系 `+1` 的玩家可见结果；
- 第一个窗口不包含主线证据效果。

**涉及文件：** `src/data/freeActionWindows.ts`、`src/data/__tests__/freeActionWindows.test.ts`、`src/types/game.ts`。

### Task 2：接入选择履历与资源结算

**内容：** 增加最小自由行动选择履历，重写第一个窗口的行动结算、银两条件、健康封顶、高强度替代和章节成长上限。

**验收：**

- 地点选择不扣资源，具体行动才结算；
- 健康接近 `100` 时只恢复实际缺口；
- 银两不足只锁付费行动；
- 高强度对练在低健康时使用确认的低强度替代；
- 结算后窗口不可再次执行。

**涉及文件：** `src/engine/gameEngine.ts`、`src/engine/__tests__/gameEngine.test.ts`、`src/types/game.ts`、`src/store/saveRepository.ts`。

### 检查点 A

- 定向数据与引擎测试通过；
- 旧存档校验不会把缺少履历的存档静默解释错误；
- 第一章流程与健康消耗测试保持通过。

### Task 3：实现地点与行动两层界面

**内容：** 将当前平铺按钮改为地点选择和行动详情；显示实际健康恢复、资源代价、锁定原因与返回地点列表。

**验收：**

- 玩家先选地点，再确认行动；
- 界面不会把内部关系数值暴露给玩家；
- 人脉名单只显示当前已认识人物；
- 返回地点列表不会消耗窗口；
- 跳过始终可见。

**涉及文件：** `src/components/FreeActionWindowView.tsx`、对应样式、`src/components/FreeActionWindowView.test.tsx`、`src/components/GameLayout.tsx`。

### Task 4：接入人物看法与结果反馈

**内容：** 根据自由行动选择履历更新人脉抽屉中的人物看法；结果页明确显示资源变化和人物反馈。

**验收：**

- 覃保坤与冯天顺使用规格中的人物看法文本；
- 关系阶段保持原样；
- 结果页区分属性资源变化与人物看法变化；
- 重新载入存档后看法仍正确。

**涉及文件：** `src/data/network.ts`、`src/components/NetworkDrawer.tsx`、`src/components/ResultPanel.tsx` 及对应测试。

### 检查点 B

- 从第一个窗口进入、选地点、完成行动、查看结果并返回主线全流程可用；
- 同一窗口不可重复结算；
- 人脉、个人档案和最近记录显示一致。

### Task 5：迁移临时实现并完成实机审查

**内容：** 删除当前临时 `+12` 恢复和直接关系数值反馈，按既定 UI 工作流进行浏览器检查与最终审查。

**验收：**

- 临时数据不再可达；
- `npm test`、`npm run typecheck`、`npm run lint`、`npm run build` 全部通过；
- 桌面浏览器中地点切换、锁定提示、结果反馈和抽屉均无布局错误；
- 不进入第二案正文或其余六个窗口。

## 四、实施顺序

`Task 1 → Task 2 → 检查点 A → Task 3 → Task 4 → 检查点 B → Task 5`

每个 Task 使用测试先行和薄切片实现。玩家试玩通过前，第一个窗口作为样板，不向其余六个窗口复制。
