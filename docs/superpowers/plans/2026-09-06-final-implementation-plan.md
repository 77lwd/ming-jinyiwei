# 《文字游戏》最终实施计划

日期：2026-09-06  
状态：用户已确认；阶段 1（运行模型与旧架构隔离）实施中  
依据：`2026-09-04-full-game-content-baseline.md`、`2026-09-05-cross-chapter-state-baseline.md`、`2026-09-04-attribute-resource-unified-review.md`、`2026-09-04-reputation-network-review.md`、`2026-09-05-asset-audio-placeholder-baseline.md`

> 2026-09-14 更新：本计划中关于 7 个自由行动窗口、5 个突发事件、事件队列与其存档兼容的内容已由 `ADR-002-retire-free-action-loop.md` 废弃。后续实现只采用章节主线、具体案件节点与固定阶段转折；其余章节剧情和资源边界仍可作为历史参考。

## 一、实施目标

把当前仍以“月份、日常事件、风险值”为核心的旧 MVP，替换为已经确认的完整游戏运行结构：

- 序章＋五章，第五章为固定终局；
- 7 个自由行动窗口；
- 4 个固定阶段事件，不做独立事件页；
- 5 个不影响主线的突发事件；
- 武力、智谋、口才、声望、人脉、健康、银两七类已确认状态；
- 既定跨章状态、互斥分支、人物经历、固定结局和角色出场边界；
- 12 位主要角色肖像、章节剧情图、音乐和占位素材的可替换接入；
- 缺少图片或音乐时，阅读、选择和主线仍可继续。

本计划只描述如何实现已经确认的内容，不重新设计剧情，不恢复月度/日常/风险系统，不增加机构信任、上峰评价、文书完整度等字段。

## 二、不可改变的实现边界

1. **旧月份架构不作为新规则的基础。** `month`、`riskLevel`、月末结算、月度事件调度和旧日常事件池必须从新运行模型中移除或隔离。
2. **主线状态以跨章状态基线为唯一来源。** 旧代码中的旗标名称如与基线冲突，以 `2026-09-05-cross-chapter-state-baseline.md` 为准。
3. **自由行动不被健康、突发事件或属性门槛整体关闭。** 健康只影响高强度选项及其代价；有空档就能行动或跳过。
4. **突发事件不是第二条主线。** 它们只允许改变健康、银两、声望、已有具名人物关系或一次性叙事反馈，并且结算后仍保留当前自由行动窗口。
5. **固定结局不设能力或关系门槛。** 周寒川牺牲、孙玉堂战死、冯天顺直属部队支援、景王兵变失败并被依法控制均为固定结果。
6. **权限必须符合普通锦衣卫校尉身份。** 廖威达只能查访、核验、护送、见证和执行获批行动；批准、封存、移交、调兵和宗亲处置由相应人物与机关完成。
7. **角色肖像不等于关系卡字段。** 肖像作为视觉资源使用；人脉页面仍只显示姓名、关系阶段和“他对你的看法”。

## 三、依赖关系与实施顺序

```text
状态/存档模型
    ↓
条件与效果引擎
    ↓
章节、自由行动、阶段事件、突发事件数据
    ↓
商店与存档流程
    ↓
叙事、行动、事件、状态、人脉、章节结束界面
    ↓
素材接入、降级处理与端到端验收
```

所有任务按依赖顺序执行。每完成一个检查点，先跑自动化验证，再进行逻辑自查；未通过不得进入下一阶段。

## 五、存档与旧代码处理原则

- 新存档必须带 schema/version 标记；
- 旧月份/风险存档只读识别，不自动迁移为新状态；
- 旧存档文件在用户主动重新开始前不删除、不覆盖；
- 旧代码先通过新入口隔离，再在全量测试通过后删除，避免边改边丢失可回退路径；
- 不使用破坏性 Git 操作，不重置用户已有文件。

## 六、主要风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 旧月份逻辑残留在组件或存档中 | 新流程出现隐性月末锁定 | 先做状态模型替换，再用 `rg` 和回归测试清理旧入口 |
| 跨章状态名称漂移 | 章节衔接或结局判断错误 | 以跨章状态基线为唯一命名表，增加状态可达性测试 |
| 健康被错误实现为窗口锁 | 自由度再次下降 | 单测明确“低健康仍可低强度行动” |
| 突发事件改变主线 | 玩家选择被无意义或强制化 | 对突发事件效果做白名单校验 |
| 肖像提前展示造成剧透 | 破坏人物揭示节奏 | 数据层增加最早展示章节/节点检查，UI 不自行提前渲染 |
| 外部素材缺失或格式不一致 | 页面空白或流程阻塞 | 所有资源都有占位、替代文本和失败回退 |
| 一次性大改导致回归困难 | 难以定位问题 | 按检查点分阶段提交，每个垂直切片先测后合并 |

## 七、明确不在本计划内的事项

- 不设计或恢复月度事件、日常事件系统；
- 不恢复风险值、风险反噬或敌方注意力数值；
- 不增加机构信任、上峰评价、文书完整度、街坊声望等状态；
- 不在本计划内生成正式图片或音乐；
- 不把突发事件扩展为第二条主线；
- 不改变已确认的章节顺序、人物身份、案件因果和固定结局。

本计划已获用户确认。当前先完成 Task 1 的运行模型替换与旧入口清理；每个检查点均需先完成自动化验证和逻辑自查，再进入下一阶段。
