# 第二章《失号凭照》最终实现规格

日期：2026-09-15  
状态：剧情与系统设计已获用户确认，等待实施计划确认  
依据：`2026-09-03-chapter-2-playtext-v2.md`、`2026-09-05-cross-chapter-state-baseline.md`、`2026-09-04-attribute-resource-unified-review.md`、`ADR-001-desktop-chapter-loop.md`、`ADR-002-retire-free-action-loop.md`

## 一、章节定位

第二章把第一章的单案办结经验扩展为三件彼此独立、但在章末程序核验中显出共同流转路径的公开案件。玩家应先把每件案子分别查清，再由总簿核验确认三种真实凭照都曾经过同一间内部转收房。

第二章只确认“流程被利用”和“转收房存在”，不确认魏承恩、景王、廖家旧案或烧焦木牌的来源。第三章承接的是独立的“已送达／未签收”文书异常，不把第二章的总簿核验改写成第三章案件。

## 二、固定流程

1. **进入第二章：三张差牌**
2. **第一案：《雨夜失押》**
3. **第二案：《空屋里的嫁妆》**
4. **第三案：《倒在更鼓前的人》**
5. **章末：失号凭照总簿核验**
6. **桥接第三章：已送达／未签收文书异常**

不得恢复旧月份、风险、自由行动窗口、随机事件池或日常循环。

## 三、第一章承接与开章奖励

### 3.1 进入条件

第一章完成依法结案并显示结章页后，结章页提供一个最小的“进入第二章”动作。该动作只负责章节切换，不改写第一章任何剧情、证据核验或结案判断。

### 3.2 固定奖励

进入第二章时，廖威达因第一案结案取得一次性办案补贴：**当前银两增加 5 两**。

- 计算方式：`next.wealth = current.wealth + 5`；沿用当前银两，不重置为固定值。
- 奖励只在第一章到第二章的实际切换动作中结算一次；重复点击、刷新或读取存档不得重复发放。
- 奖励必须出现在章节进入后的状态变化记录中，文案明确写出“第一案结案补贴：银两 +5”。
- 不新增玩家可见资源字段或奖励货币。

### 3.3 承接状态

| 类别 | 承接内容 | 第二章边界 |
|---|---|---|
| 人脉 | 覃保坤已进入人脉；冯天顺已因第一章末重逢进入人脉 | 覃保坤负责批准、分开看守、封存和程序承接；冯天顺只允许出现一小段非案件日常，不提供军情或权限 |
| 属性 | 武力、智谋、口才、声望保留当前值 | 不因进入第二章自动加点；属性不能替代证据或权限 |
| 资源 | 健康、银两保留当前值，随后先结算银两 +5 | 不重置、不创建章节专属资源；未写明的选择不扣资源 |
| 证据与案件记录 | `first_case_closed` 作为第一案合法履历；第一章证据归档 | 第一章材料不作为第二章三案的证据，除非正文明确引用程序履历 |
| 烧焦木牌线索 | `charred_token_preserved` 独立封存 | 第二章开章明确“不碰它”；不得解释来源、复制木牌或把它并入三案证据 |
| 个人前史 | `prologue_survivor` 保留 | 只作为个人经历，不提供第二章案件答案 |

## 四、案件实现契约

每案都采用“场景叙事 → 具体取证 → 一次调查顺序选择 → 证据整理 → 责任边界说明”的节奏。选择只改变保留下来的证据侧重和后续对白，不改变三案必然完成或章末总簿核验可达。

### 4.1 《雨夜失押》

- 核心问题：马骁并非自行挣脱；真凭照被用于一次未核验的违规交接。
- 廖威达可做：查看锁具、翻车方向、拖痕、押役口供、河埠船夫与湿存根。
- 覃保坤权限：分开看守、批准询问、封存凭照、拆分失职与收钱责任。
- 互斥结果：
  - `c2_01_responsibility_chain`：保住两份原始口供、锁具记录和翻车现场，河埠路线仅保留模糊方向；
  - `c2_01_route_chain`：保住船夫、茶棚伙计和领取别号，押役责任口供被统一过。
- 完成摘要：`slip_chain_1`。

### 4.2 《空屋里的嫁妆》

- 核心问题：卢小绫是主动躲藏以保护继承文书；舅父存在债务胁迫；中间人滥用真实封验凭照施压取契。
- 廖威达可做：核验靛色脚印、衣带、继承副契原件与抄件、债册、茶摊交接记录和证言。
- 覃保坤权限：请求地方衙门守住废染坊、主持当面核验、批准副契封存。
- 互斥结果：
  - `c2_02_witness_deed`：保住卢小绫人证与副契链；
  - `c2_02_receipt_chain`：保住凭照交割链，但副契原件受损，转为抄件。
- 必须分别记录：自愿躲藏、舅父胁迫、凭照滥用，不能合并成单一“绑架”结论。
- 完成摘要：`slip_chain_2`。

### 4.3 《倒在更鼓前的人》

- 核心问题：程佑死亡、赵培先前殴打、冯六收钱放行及夜守簿改写必须按时间顺序拆开。
- 廖威达可做：核验尸体位置、门闩血迹、更鼓时刻、夜放牌副券、改写值夜簿、货封记录与书吏证言。
- 权限边界：廖威达只能勘验、记录和呈报；拘押、封存和责任处理由获批上官完成。
- 固定五步时间链：赵培先与程佑冲突 → 冯六收钱放车 → 门闩处争夺副券并致伤 → 程佑倒在更鼓前 → 值夜簿被改写。
- 互斥结果：
  - `c2_03_death_chain`：保住死亡现场与时序责任链；
  - `c2_03_record_chain`：保住改簿、放行和货封记录链。
- 完成摘要：`slip_chain_3`。

## 五、章末总簿核验

覃保坤取得书面授权后，仅检查百户所发放、注销、封存总簿及三案材料。覃保坤主持，书记官抄录，库吏解释流程，廖威达逐项比对。

核验必须得到以下事实：

- 三种不同凭照都被标为“误印／待回收”，却尚未剪角注销；
- 三张凭照均经过同一间内部转收房；
- 转收房收件簿存在缺页或改动；
- 封存前依法制作盖印副本；
- 后续封蜡被破坏，缺口被扩大。

章末固定写入：

- `c2_transfer_room_identified`
- `c2_register_copy_preserved`
- `c2_register_tampered`

以上事实只能证明流程异常和材料被动过，不能确认经手人、魏承恩、景王或烧焦木牌来源。

## 六、属性、资源与代价

- 第二章不自动奖励武力、智谋、口才或声望；结案只记录玩家处理过的压力类型。
- 健康和银两沿用跨章当前值，不因章节开始重置。
- 只有玩家明确选择了需要支出的做法，才允许产生健康或银两变化；选项文字必须在确认前显示代价、数量和后果。
- 第二章当前已确认的数值变化只有：进入第二章时银两 `+5`。
- 正文未写明的雇人、车马、抄件、诊治或夜查费用不得由实现擅自添加；如后续要加入，必须先更新本规格并重新确认。
- 资源不足时保留基本程序路线，不能因贫困或低健康直接关闭案件或章节。

## 七、界面与素材边界

- 沿用第一章“克制的小说叙事 + 具体办案动作 + 少量留白”的文本与交互标准。
- 案件界面必须显示当前案、已固定事实、待核问题、互斥调查顺序和选择后果。
- 章末总簿核验使用专用核验工作台；不得复用第一章证据组合规则造成全选通过，也不得把三案材料混成一个案件。
- 缺图时仍可阅读、取证、选择和结案；本阶段不生成图片。
- 外部素材需求仅列清单：雨夜河埠翻车现场、城南空屋与废染坊、城门值房与更鼓前尸体、百户所总簿核验桌面；每项需提供 16:9 桌面背景、无文字版本和可读替代文本。

## 八、非目标

- 不改写第一章正文、证据组合、夜间保全规则或第一章结案逻辑；
- 不恢复月份、风险、自由行动、随机事件、机构信任或旧月份存档解释；
- 不新增玩家可见属性、资源、关系字段或匿名人物关系；
- 不在第二章揭示魏承恩、景王、廖家旧案真相或烧焦木牌来源；
- 不生成或接入正式图片素材。

## 九、验收标准

1. 第一章结章页可一次性进入第二章，并且只获得一次银两 `+5`。
2. 第二章按固定顺序完成三案和总簿核验；旧 `chapter2.paper-note-review` 不再作为流程节点。
3. 三案各自写入完成摘要和且只能一个互斥分支。
4. 章末三个固定状态全部写入，且不越权生成第三章或第五章结论。
5. 任何未明确标价的选择不改变健康或银两；没有自动属性奖励。
6. 第一章现有测试和行为保持不变，第二章新增测试覆盖存档恢复、奖励幂等、分支互斥、总簿固定状态和 UI 结果反馈。
