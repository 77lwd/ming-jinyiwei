# 自由行动系统退役与新版基线

日期：2026-09-12  
状态：旧系统退役已实施；新版结构已确认，第一个窗口内容设计中

## 1. 决定

现有旧版自由行动系统直接作废，不再作为玩家可见流程、兼容入口或新版实现基础。旧系统包括通用行动卡、重复执行、统一“占用 1 个窗口”提示、自由行动窗口计数页，以及与月份/日常循环绑定的展示和结算。

## 2. 作废范围

- 休养、整理案卷、巡街执勤、练习刀法、练习应对等通用行动卡；
- 找周寒川说话、给冯天顺递信、承接合规差事等旧版关系/公务卡；
- “自由行动窗口 1/7”作为菜单标题的玩家可见展示；
- 可重复刷属性、银两或关系的行动逻辑；
- 旧月份、月度事件、日常事件池、月末结算和风险路径。

## 3. 必须保留

- 新状态机表达全篇 7 个自由行动窗口的能力；
- 窗口按既定主线空档顺序开放，每个窗口只能处理一次主要行动或跳过；
- 健康只改变高强度做法和代价，不关闭窗口；
- 突发事件结算后回到原窗口，不吞掉窗口；
- 行动只能影响已确认的状态范围，不新增系统、数值或人物关系字段。

## 4. 玩家可见规则

- 第一章《纸灰里的银子》不设置自由行动窗口；
- 第一章结案后不得出现旧行动菜单或提前展示窗口计数；
- 后续窗口必须绑定明确的主线间隙和具体情境；
- 行动结果必须是一次性、可感知的叙事或状态差异，不显示通用刷取选项；
- 未完成新版数据与流程前，宁可不显示窗口，也不得显示旧菜单冒充成品。

## 5. 实施顺序

1. 为旧入口和旧逻辑补充“不可从第一章进入”的回归测试。
2. 从 `GameLayout` 隔离旧 `ActionGrid` 玩家入口，但暂不删除新状态机字段。
3. 将旧 `freeActions` 数据从运行时装配中移除，并删除只服务旧菜单的测试。
4. 建立新版窗口数据接口和一次性结算测试。
5. 先接入一个经过确认的窗口做垂直切片，再扩展其余窗口。
6. 完成浏览器试玩、旧入口扫描和最终审查。

## 6. 验收标准

- 第一章从标题页到结案全过程不出现自由行动界面；
- 旧行动标签和“安排这一段空档”不再被玩家流程渲染；
- 全局仍能表达 7 个窗口，且窗口索引不会被行动重复或突发事件改变；
- 新行动不可重复刷取，跳过后窗口按规则进入下一节点；
- `npm test`、`npm run typecheck`、`npm run lint`、`npm run build` 通过。

## 7. 不做

- 不恢复月份、风险、行动点或日常循环；
- 不为第一章擅自新增自由行动；
- 不在没有对应剧情数据时虚构 7 个窗口的具体内容；
- 不进入第二章及后续章节开发。

## 8. 新版自由行动的因果方向

自由行动统一采用“玩家先选择行动，行动再改变资源属性”的因果方向。属性和资源可以改变行动结果、成本或高强度做法，但不得替玩家决定行动，也不得关闭整个窗口。

- 每个窗口先显示符合当前情境的地点，再显示该地点的一次性行动；
- 每个窗口只能完成一项主要行动，也可以跳过；
- 行动结果只更新武力、智谋、口才、声望、健康、银两或已经认识的具名人物关系；
- 自由行动不得生成主线证据、提前调查下一案、替代正式权限或改变固定结局；
- 七个窗口的地点和具体行动随章节情境变化，不得重复使用同一套通用菜单；
- 能力成长必须有场景、成本和阶段上限，不能连续选择同一行为无限刷取。

## 9. 健康恢复与银两成本基线

第一个自由行动窗口采用下列恢复比例作为设计基准：

| 行动 | 结算 | 定位 |
| --- | --- | --- |
| 回住处睡半日 | 健康 `+8` | 免费自然恢复，效果最低但不消耗银两 |
| 医馆简单处理 | 银两 `-2`、健康 `+12` | 低成本诊治，必须优于免费休息 |
| 医馆仔细诊治 | 银两 `-6`、健康 `+20` | 恢复效果最高，保留明确资金取舍 |
| 食肆正常用饭 | 银两 `-2`、健康 `+4` | 只能缓解疲劳，不能替代治伤 |

食肆或其他生活行动若恢复效率低于医馆，必须同时提供合理的生活场景、同僚交往或其他非治疗价值，不能成为单纯更贵且更差的恢复按钮。

健康不足只能关闭或改变具体高强度行动。住处休息、合规诊治、低强度事务、人物拜访和跳过始终保留。

## 10. 人脉行动的玩家可见结算

人脉页面和行动结果只向玩家显示：

- 人物姓名；
- 关系阶段；
- 他对廖威达的看法。

不得向玩家显示“关系 `+1`”“好感度”或关系进度条。普通拜访、吃饭、闲谈和生活帮助通常只更新“他对主角的看法”，不会自动推动关系阶段。

关系阶段只在有足够剧情意义的事件中明确变化，并以“熟悉 → 信任”等阶段变化呈现。普通行动不得通过重复拜访把人物关系刷到信任或亲近。

第一个窗口中的示例结果：

- 拜访覃保坤：关系阶段保持不变；看法可以更新为“他认为你办差后仍愿意反省自己的疏漏，不是只惦记邀功的人”；
- 拜访冯天顺：关系阶段保持不变；看法可以更新为“他确认你没有因为入了锦衣卫便疏远旧交，与你相处也比刚重逢时自在”。

人物名单必须根据当前已经认识的人动态产生。未认识的人不显示；人物拜访不提供案件答案、主线证据或额外权限。

## 11. 当前临时实现说明

第一个窗口现有代码仅用于验证“选择行动 → 资源结算 → 窗口一次性完成”的技术闭环。下列内容不是最终设计：

- 住处恢复健康 `+12`；
- 食肆、医馆等尚未完成正式地点分层；
- 人物行动使用内部关系数值直接结算或显示。

正式实施必须先根据本文件完成第一个窗口的地点与行动表，再以测试先行方式替换临时数据。不得把临时数值视为玩家已经确认的最终平衡。

## 12. 第一个自由行动窗口正式内容

### 12.1 窗口位置与结构

位置：第二章第一案《雨夜失押》完成移交后、第二案《空屋里的嫁妆》开始前。

玩家流程固定为：

`进入空档 → 选择地点 → 选择一项行动 → 展示小场景和资源结果 → 返回主线`

开放地点为住处、医馆、校场、署内、城中和人脉。每个窗口只能完成一项主要行动，也可以直接回署。地点选择本身不结算资源。

### 12.2 正式行动表

| 地点 | 行动 | 资源结算 | 约束与定位 |
| --- | --- | --- | --- |
| 住处 | 睡上半日 | 健康 `+8` | 免费、稳定，不增加其他属性 |
| 住处 | 收拾住处并做顿热食 | 银两 `-1`、健康 `+10` | 低成本生活恢复，不牵强增加能力 |
| 医馆 | 处理最碍事的伤处 | 银两 `-2`、健康 `+12` | 低成本诊治，必须优于免费休息 |
| 医馆 | 仔细诊治并带药 | 银两 `-6`、健康 `+20` | 本窗口恢复最高，保留资金取舍 |
| 校场 | 独自操练短刀 | 健康 `-5`、武力 `+1` | 中等强度，不改变声望或人脉 |
| 校场 | 与值守同僚对练 | 健康 `-8`、武力 `+1`、声望 `+1` | 高强度；健康不足时改为低强度协助，健康 `-2`、声望 `+1`，不增加武力 |
| 署内 | 研读公开成例 | 健康 `-3`、智谋 `+1` | 不接触下一案材料，不生成证据 |
| 署内 | 替同僚接一轮值守 | 健康 `-4`、声望 `+1` | 普通校尉差务，不增加银两 |
| 署内 | 请老书吏指点正式呈报 | 健康 `-3`、口才 `+1` | 练习如何清楚呈报事实与请求，不靠无目的闲聊成长 |
| 城中 | 请几名同僚吃顿便饭 | 银两 `-4`、健康 `+3`、声望 `+1` | 普通同僚不进入人脉页，不提供案情 |
| 城中 | 承接一次短途护送 | 健康 `-7`、银两 `+5` | 由署内批准、报酬来源明确；本窗口一次性，不形成赚钱循环 |
| 人脉 | 登门拜访覃保坤 | 关系阶段不变；更新人物看法 | 不谈下一案，不提供权限或证据 |
| 人脉 | 与冯天顺沿旧街走走 | 健康 `-2`；关系阶段不变；更新人物看法 | 仅在已经重逢后显示，不提供军中或案件情报 |
| 人脉 | 请冯天顺吃顿便饭 | 银两 `-2`、健康 `+3`；关系阶段不变；更新人物看法 | 花钱不会额外推动关系阶段 |
| 返回 | 不作安排，按时回署 | 状态不变 | 无惩罚地跳过本窗口 |

### 12.3 平衡审查结论

- 删除“随意走走”：其免费健康恢复被住处休息完全覆盖，属于机械假选项；
- 删除“独自在食肆吃饭”：同价医馆恢复显著更高，只有氛围差异不足以支撑独立资源选择；
- 保留“请同僚吃饭”：它以银两换取少量健康和公开声望，与医馆的纯恢复作用不同；
- 武力、智谋和口才在第二章分别最多通过自由行动提高一次；达到上限后必须提供不增加该属性的情境替代行动；
- 同一种护送、值守、训练或拜访不能在同一窗口重复，也不得跨窗口原样复制形成刷取；
- 健康最高为 `100`，恢复类行动必须显示当前实际可恢复量；
- 银两不足只关闭对应付费行动；健康不足只关闭或替换具体高强度行动；
- 人脉行动不向玩家显示关系数值，普通拜访不推动关系阶段。

### 12.4 人物看法结果

- 拜访覃保坤后：关系阶段保持原样；看法更新为“他认为你办完差后还愿意回想自己的疏漏，不是只惦记邀功的人”；
- 与冯天顺沿旧街走后：关系阶段保持原样；看法更新为“他确认你仍记得旧日相处的分寸，与你说话也比刚重逢时自在”；
- 请冯天顺吃饭后：关系阶段保持原样；看法更新为“他知道你没有因为进了锦衣卫便疏远旧交，但也不愿让你总替他花钱”。

为了保存玩家实际选择及其人物看法结果，实施时只允许增加最小的自由行动选择履历。该履历不属于新关系数值，不向玩家显示进度，也不能被用于主线证据或权限判断。
